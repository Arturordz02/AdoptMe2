1. CONTENIDO DEL PAQUETE
--------------------------------------------------------------------------------
Este archivo ZIP contiene el código fuente completo del proyecto AdoptMe:

- Android/  : Proyecto completo para Android Studio en Kotlin y Jetpack Compose.
- Backend/  : Solución completa Web API en ASP.NET Core 8 (.NET 8).
- LEEME.txt : Documento informativo sobre estructura, apertura y estado del avance.


2. GUIA DE APERTURA Y EJECUCION
--------------------------------------------------------------------------------
A. PROYECTO ANDROID (Carpeta "Android"):
   - Abrir Android Studio (Hedgehog, Koala, Ladybug o superior).
   - Seleccionar "Open" y elegir la carpeta "Android" de este paquete.
   - Requisito: JDK 17 o superior configurado en Android Studio.
   - Android Studio descargará automáticamente las dependencias de Gradle y
     generará el archivo "local.properties" con la ruta local de tu SDK.
   - La aplicación ya viene configurada para conectarse por defecto a la API
     desplegada en Azure por HTTPS mediante Retrofit.

B. PROYECTO BACKEND (Carpeta "Backend"):
   - Abrir "Backend/AdoptMe.Api.slnx" en Visual Studio 2022 o abrir la carpeta
     "Backend/AdoptMe.Api" en Visual Studio Code.
   - Requisito: .NET 8.0 SDK instalado.
   - Para compilar desde terminal:
     dotnet build
   - Nota sobre ejecucion local del backend:
     Por motivos de seguridad, la clave secreta JWT (Jwt:Key) y la cadena de
     conexion real a Azure SQL no se incluyen en este paquete. Para ejecutar el
     backend localmente, cada desarrollador debe configurar su propia clave JWT
     de al menos 32 caracteres y su cadena de conexion a base de datos (por
     ejemplo usando 'dotnet user-secrets' o variables de entorno locales).
     No se garantiza el funcionamiento del backend en local sin configurar
     dichos parametros privados.


3. API EN AZURE Y VERIFICACION JWT
--------------------------------------------------------------------------------
- La API backend se encuentra desplegada y operativa en produccion en Azure:
  https://adoptme-api-bzc8h7fdb3hcccac.westus3-01.azurewebsites.net

- Estado de verificacion en la nube:
  * Registro y login operativos contra Azure SQL.
  * Emision de tokens JWT firmados con vigencia de 2 horas.
  * El endpoint protegido 'GET /api/Usuarios/sesion' con [Authorize] fue
    desplegado y verificado exitosamente en Azure:
    - Peticion sin token: devuelve HTTP 401 Unauthorized.
    - Peticion con token falso/alterado: devuelve HTTP 401 Unauthorized.
    - Peticion con token JWT valido obtenido en login: devuelve HTTP 200 OK
      y confirma la identidad del correo autenticado.


4. ESTADO REAL DEL PROYECTO
--------------------------------------------------------------------------------
A. FUNCIONALIDADES IMPLEMENTADAS Y PROBADAS:
   [Backend]
   - Modelos de datos (Usuario, Mascota) y DTOs de autenticacion.
   - Hashing criptografico de contrasenas mediante IPasswordHasher<Usuario>.
   - Generacion y validacion de tokens JWT con claims de identidad y rol.
   - Endpoint protegido 'GET /api/Usuarios/sesion' probado y validado en Azure.
   - Endpoints de consulta de catalogo 'GET /api/Mascotas' y 'GET /api/Mascotas/{id}'.

   [Android]
   - Arquitectura declarativa con Jetpack Compose y Material 3.
   - Navegacion por perfiles de usuario (Adoptante, Centro, Administrador).
   - Pantallas de Catalogo, Detalle de Mascota, Favoritos y Notificaciones.
   - Sistema de preferencias de usuario (tema claro/oscuro, colores y tamano de texto).
   - Cliente HTTP Retrofit configurado hacia Azure con conversor Gson y logging.
   - Pantallas de Registro e Inicio de Sesion conectadas a la API de Azure.
   - Recepcion y mantenimiento en memoria del token JWT durante la sesion activa.
   - Carga reactiva del listado de mascotas desde la API de Azure.

B. FUNCIONALIDADES PENDIENTES / EN DESARROLLO:
   - Las operaciones de creacion, edicion y eliminacion de mascotas en la API
     estan actualmente reservadas ([NonAction]) y deben habilitarse en el backend.
   - En Android, las solicitudes de adopcion y creacion de publicaciones aun
     se gestionan mediante almacenamiento local (AppStorage/SharedPreferences) y
     deben conectarse a la API REST.
   - La persistencia segura del JWT en almacenamiento local de Android (ej.
     EncryptedSharedPreferences/DataStore) y el AuthInterceptor de OkHttp para
     enviar el token automaticamente en cada peticion protegida estan pendientes.
   - Validacion automatica de la vigencia de sesion en el arranque de la app.
   - No existe integracion de Firebase en el estado actual.


5. REQUISITOS REALES DE LAS PRACTICAS (PC08, PC09 Y PC10)

  * Estado: PENDIENTE.
  * Requiere la integracion con servicios de Firebase (Firebase Authentication,
